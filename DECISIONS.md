# Decisions

- 2026-11-07 — Sim modules live in `config/` and `sim/` (outside `scripts/`), because the engine auto-loads every file in `scripts/`; the engine entry will require them later. Reason: keeps headless sim testable with plain Lua.
- 2026-11-07 — GR5-2 foundation uses a single `config/balance.luau` table; to be split into `config/*.luau` per subsystem as milestones add content. Reason: simplest for M0.
- 2026-11-07 — `tickSeconds = 0.1` (10 Hz, spec §7). Durations in balance are now expressed in game seconds (`jumpSeconds`, `scanSeconds`, `ai.delaySeconds*`, `mineRatePerSecond`) and converted via `Sim:ticks()`, so wall-clock behavior is unchanged by the tick rate. Reason: avoids a cross-cutting rebalance if the tick rate changes.
- 2026-11-07 — Planets, veins settings and `startBuyer` moved to `config/world.luau` (spec §4/§16.1); `balance.luau` keeps only tunables. Markets/routes stay inside planet entries for now. Reason: simplest split matching the spec layout.
- 2026-11-07 — GR5-24: AYLO has no `require` (rtype docs/scripting/plan.md D6). Modules are now plain globals (`Balance`, `World`, `Sim`, `Ai`) under `scripts/` (moved from top-level `config/`, `sim/`) so the engine loads them in sorted path order; `config/` sorts before `main.luau` and `sim/`. Headless tests load files via `tests/load_scripts.lua`, which mimics that loader (no `require`). Reason: only way code loads under the real runtime.
- 2026-11-07 — GR5-21: icons kept as vector SVG with `currentColor` (not pixelated), tinted at runtime from the theme table; reason: GR5-3 theme not in repo yet, vector tint keeps one source of truth. Icon picks listed in tools/build_icons.py; attribution generated to CREDITS_ICONS.md.
- 2026-11-07 — GR5-24: icon modules are globals `IconSet` (scripts/ui/icon_set.luau, generated) and `IconStyle`; icon_set sorts before icon_style so no require is needed. Reason: AYLO has no `require`.
- 2026-11-07 — GR5-22 VFX modules return pure draw-parameter tables (render/vfx/*.luau, config/vfx.luau); the actual shader/draw calls are wired later once the engine's rendering API is documented. Reason: no render API in the repo/template, and logic stays headless-testable.
- 2026-11-07 — Glitch source whitelist lives in config (`allowedSources = ai_error`); UI/log code must call `glitch.trigger(g, "ai_error")` from the ERROR event only. Reason: acceptance criterion "never from idle/hover".
- 2026-11-07 — GR5-24: VFX modules are globals (`VfxConfig`, `Bloom`, `Glitch`, `Halo`, `Route`, `Trail`) under `scripts/config/vfx.luau` and `scripts/render/vfx/*`, since AYLO has no `require` and loads scripts/ in sorted order. Test needs a loader that does the same (no standalone `luau` interpreter is available here, so vfx_test is unexecuted locally).
- 2026-11-07 — Planets: one parameterised fragment shader (`assets/shaders/planet.glsl`) rewritten from Deep-Fold's MIT algorithm rather than copying defold-pixel-planets files — that repo has no license file (GitHub reports none), only a credit-to-Deep-Fold README.
- 2026-11-07 — Planets: one shader for all 4 planets (land/water/clouds via uniforms; waterLevel 0 + no clouds = barren/lava), instead of one shader per Deep-Fold variant — simplest, one asset pipeline.
- 2026-11-07 — Planets: drawn as an `rtype.SpriteRenderer` on a shared 4x4 white texture (`assets/textures/white.png`) because `ShapeRenderer` has no material field. That texture is shared by all planets, not a per-planet asset.
- 2026-11-07 — Planets: palette is passed to the shader per material from `GameConfig.palette` (placeholder 8 colours until GR5-3); `Planet.new` asserts every colour name is in the palette, so no second remap pass is needed.
- 2026-11-07 — Trade planets (Meridian Base, Halcyon Port) get the same rotating planet treatment as harvest planets (issue default).
- 2026-11-07 — Config lives in `scripts/config/planets.luau` (only `scripts/` is auto-loaded, no `require`); globals `GameConfig`, `Planet`.
- 2026-11-07 — Asteroids/stars/galaxy: reuse the planet shader via Planet.fromDef (waterLevel 0, no clouds, small radius/pixels); config in scripts/config/bodies.luau. Hidden vein = dark rock at base size; revealed = size + lit-colour tier by richness (rebuild with Asteroid.new(..., true) and swap SpriteRenderer on scan). "?" is UI, not sprite.
- 2026-11-07 — Galaxy: defaulted to a decorative distant sprite (layer -100, low detail), not the star-map screen backdrop (GR5-3). Star.new is the single star renderer; GR5-17 should call it.
- 2026-11-08 — GR5-2 rework: world/balance aligned to GDD_spec_MVP_EN v1 (ids/names kessa/varn/ashfall/lumen + orbis/halcyon/meridian, 4 ores with base price+hardness, 12 veins, depot rates, travel tables, markets as data in `config/world.luau`; start 500 cr / 10 Compute; hold 100, drill 2/s; `wait` in tier 1). Reason: spec overrides the earlier placeholders. Render keys in `config/planets.luau` renamed to the same ids; ashfall/lumen looks are placeholder seeds.
- 2026-11-08 — Sim keeps a single-ore hold (mine rejects a different ore while cargo > 0) and only the HMC depot buyer for now; Orbis/Halcyon/Meridian are data only until the market/warehouse milestones. Reason: simplest option that satisfies M2; spec's mixed hold needs the sell-by-resource tool args.
- 2026-11-08 — `Sim:context` returns a deep detached snapshot (hidden veins omitted, unscanned veins expose a richness band only, per spec §4.3). Late AI answers go through `Sim:resolveDecision`: dropped as `stale` if the ship state changed since the snapshot, otherwise `apply` re-validates every precondition against live state. Reason: async providers (GR5-15) must not trust or mutate captured state.
- 2026-11-08 — Tool args follow spec §11 names (`vein` id, `destination`, `message`, `seconds`); `scan` takes 10 s of ship time and no Compute cost; flat `computePerDecision` stays a placeholder until token-based costing (spec §6.4). `tests/load_scripts.lua` loads only `scripts/config` and `scripts/sim` since client/render/ui use Luau syntax that plain Lua cannot parse.
