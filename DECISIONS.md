# Decisions

- 2026-11-07 — Sim modules live in `config/` and `sim/` (outside `scripts/`), because the engine auto-loads every file in `scripts/`; the engine entry will require them later. Reason: keeps headless sim testable with plain Lua.
- 2026-11-07 — GR5-2 foundation uses a single `config/balance.luau` table; to be split into `config/*.luau` per subsystem as milestones add content. Reason: simplest for M0.
- 2026-11-07 — `tickSeconds = 0.1` (10 Hz, spec §7). Durations in balance are now expressed in game seconds (`jumpSeconds`, `scanSeconds`, `ai.delaySeconds*`, `mineRatePerSecond`) and converted via `Sim:ticks()`, so wall-clock behavior is unchanged by the tick rate. Reason: avoids a cross-cutting rebalance if the tick rate changes.
- 2026-11-07 — Planets, veins settings and `startBuyer` moved to `config/world.luau` (spec §4/§16.1); `balance.luau` keeps only tunables. Markets/routes stay inside planet entries for now. Reason: simplest split matching the spec layout.
- 2026-11-07 — GR5-24: AYLO has no `require` (rtype docs/scripting/plan.md D6). Modules are now plain globals (`Balance`, `World`, `Sim`, `Ai`) under `scripts/` (moved from top-level `config/`, `sim/`) so the engine loads them in sorted path order; `config/` sorts before `main.luau` and `sim/`. Headless tests load files via `tests/load_scripts.lua`, which mimics that loader (no `require`). Reason: only way code loads under the real runtime.
- 2026-11-07 — GR5-21: icons kept as vector SVG with `currentColor` (not pixelated), tinted at runtime from the theme table; reason: GR5-3 theme not in repo yet, vector tint keeps one source of truth. Icon picks listed in tools/build_icons.py; attribution generated to CREDITS_ICONS.md.
- 2026-11-07 — GR5-24: icon modules are globals `IconSet` (scripts/ui/icon_set.luau, generated) and `IconStyle`; icon_set sorts before icon_style so no require is needed. Reason: AYLO has no `require`.
- 2026-11-07 — GR5-22 VFX modules return pure draw-parameter tables (render/vfx/*.luau, config/vfx.luau); the actual shader/draw calls are wired later once the engine's rendering API is documented. Reason: no render API in the repo/template, and logic stays headless-testable.
- 2026-11-07 — Glitch source whitelist lives in config (`allowedSources = ai_error`); UI/log code must call `glitch.trigger(g, "ai_error")` from the ERROR event only. Reason: acceptance criterion "never from idle/hover".
- 2026-11-07 — GR5-24: VFX modules are globals (`VfxConfig`, `Bloom`, `Glitch`, `Halo`, `Route`, `Trail`) under `scripts/config/vfx.luau` and `scripts/render/vfx/*`, since AYLO has no `require` and loads scripts/ in sorted order. Test needs a loader that does the same (no standalone `luau` interpreter is available here, so vfx_test is unexecuted locally).
- 2026-11-07 — Planets: one parameterised fragment shader (`assets/shaders/planet.glsl`) rewritten from Deep-Fold's MIT algorithm rather than copying defold-pixel-planets files — that repo has no license file (GitHub reports none), only a credit-to-Deep-Fold README.
- 2026-11-07 — Planets: one shader for all 4 planets (land/water/clouds via uniforms; waterLevel 0 + no clouds = barren/lava), instead of one shader per Deep-Fold variant — simplest, one asset pipeline.
- 2026-11-07 — Planets: drawn as an `rtype.SpriteRenderer` on a shared 4x4 white texture (`assets/textures/white.png`) because `ShapeRenderer` has no material field. That texture is shared by all planets, not a per-planet asset.
- 2026-11-07 — Planets: palette is passed to the shader per material from `GameConfig.palette` (placeholder 8 colours until GR5-3); `Planet.new` asserts every colour name is in the palette, so no second remap pass is needed.
- 2026-11-07 — Trade planets (Meridian Base, Halcyon Port) get the same rotating planet treatment as harvest planets (issue default).
- 2026-11-07 — Config lives in `scripts/config/planets.luau` (only `scripts/` is auto-loaded, no `require`); globals `GameConfig`, `Planet`.
- 2026-11-07 — Asteroids/stars/galaxy: reuse the planet shader via Planet.fromDef (waterLevel 0, no clouds, small radius/pixels); config in scripts/config/bodies.luau. Hidden vein = dark rock at base size; revealed = size + lit-colour tier by richness (rebuild with Asteroid.new(..., true) and swap SpriteRenderer on scan). "?" is UI, not sprite.
- 2026-11-07 — Galaxy: defaulted to a decorative distant sprite (layer -100, low detail), not the star-map screen backdrop (GR5-3). Star.new is the single star renderer; GR5-17 should call it.
- 2026-11-08 — GR5-2 rework: world/balance aligned to GDD_spec_MVP_EN v1 (ids/names kessa/varn/ashfall/lumen + orbis/halcyon/meridian, 4 ores with base price+hardness, 12 veins, depot rates, travel tables, markets as data in `config/world.luau`; start 500 cr / 10 Compute; hold 100, drill 2/s; `wait` in tier 1). Reason: spec overrides the earlier placeholders. Render keys in `config/planets.luau` renamed to the same ids; ashfall/lumen looks are placeholder seeds.
- 2026-11-08 — Sim keeps a single-ore hold (mine rejects a different ore while cargo > 0) and only the HMC depot buyer for now; Orbis/Halcyon/Meridian are data only until the market/warehouse milestones. Reason: simplest option that satisfies M2; spec's mixed hold needs the sell-by-resource tool args.
- 2026-11-08 — `Sim:context` returns a deep detached snapshot (hidden veins omitted, unscanned veins expose a richness band only, per spec §4.3). Late AI answers go through `Sim:resolveDecision`: dropped as `stale` if the ship state changed since the snapshot, otherwise `apply` re-validates every precondition against live state. Reason: async providers (GR5-15) must not trust or mutate captured state.
- 2026-11-08 — Tool args follow spec §11 names (`vein` id, `destination`, `message`, `seconds`); `scan` takes 10 s of ship time and no Compute cost; flat `computePerDecision` stays a placeholder until token-based costing (spec §6.4). `tests/load_scripts.lua` loads only `scripts/config` and `scripts/sim` since client/render/ui use Luau syntax that plain Lua cannot parse.
- 2026-11-08 — GR5-17 background: ported Deep-Fold PixelSpace (Nebulae.shader + StarStuff.shader, both already GLSL, MIT) to `assets/shaders/background.glsl`, one shader with `mode` 0 nebula / 1 dust+stars. Reason: the shader reader pattern now exists (planet.glsl) and the source was GLSL, so the "try the port first" path was cheap.
- 2026-11-08 — Background colours are a 4-step ramp + 2 star colours of palette names; the shader only selects between uniforms (step/mix with 0 or 1), never blends, so output is always one of them. Dropped the original's `should_tile`/`colorscheme` texture. Config in `config/background.luau`, builder `Background.new(screenId, size, position)` in `client/background.luau` returns layer descriptions back to front.
- 2026-11-08 — Parallax comes from stacking 2 shader layers with different `drift`, not from a recoloured art pack. The OpenGameArt "Space Background 3" page is CC0 (read 2026-11-08), so it stays a free fallback with no credits obligation, but is unused. Big stars are not in this shader: callers use Star.new.
- 2026-11-08 — Migrated every script to real `require()` (rtype #498-#504 shipped it, with entry points and a per-file sandbox): each module `return`s its table and requires its dependencies with `@scripts/...` (or `./` inside a folder). No more global `Balance`/`World`/`Sim`/`Ai`/`GameConfig`/`VfxConfig`/`Planet`/`IconSet`/... Supersedes the earlier "no require, sorted-load globals" entries. Reason: reviewer asked for it, and the new engine stops auto-loading files and gives each file its own globals, so the globals would silently stop working. Needs an engine build that includes rtype #504.
- 2026-11-08 — `GameConfig` is gone: `config/planets.luau` returns `{ palette, planetRender, planets }` and `config/bodies.luau` returns `{ asteroid, star, galaxy }`; `client/bodies.luau` returns `{ Asteroid, Star, Galaxy }`. Reason: one module per file, no merged global.
- 2026-11-08 — `Ai.mode` became `Ai.setMode("stub" | "vague")` over a local: the engine freezes a returned table, so writing a field on it fails. Tests freeze the module tables too, to catch any other write.
- 2026-11-08 — `client/planet.luau` and `client/bodies.luau` no longer return early when `not engine.isClient`: an early `return` would hand server code a `nil` module, and the engine calls inside them only run when a function is called. Reason: `require` must always give a table.
- 2026-11-08 — Entries: kept the default `scripts/main.luau` (the template counter) and set no `scripts.*` keys. Nothing requires sim/UI/render modules yet because their consumers (server tick system, screens) arrive with later milestones; the first of them adds its `require` to the entry. Reason: simplest, and a file no entry requires never runs.
- 2026-11-08 — Tests run on the Luau CLI (`luau tests/test_headless.luau`, `luau tests/vfx_test.luau`, from the repo root) using the same `@scripts/...` paths as the game, via a `.luaurc` alias; `tests/load_scripts.lua` and the Lua 5.4 workaround are removed. Fixed `vfx_test.luau`, whose route dash-offset check used `t = 0.5` (offset (0.5 x 40) % 20 = 0) and had never passed.
- 2026-11-08 — GR5-27 M0 gate = `tests/test_m0.luau` (modules load, balance anchors, empty save round-trips byte-identical, 10 Hz headless run) plus `tools/run_tests.sh`, which runs every `tests/*.luau` on the Luau CLI and fails on the first error. Reason: the simplest runner that needs nothing but the CLI; no CI workflow added.
- 2026-11-08 — Save = `sim/persistence.luau` (+ `sim/json.luau`, since the engine has no JSON: docs/Http.md). File access is an injected `storage {read, write}` because the engine has no file API [ENGINE, tracked by the Engine Agent]; `memoryStorage()` is used headless. `schema_version = 1`, exact match required (no migrations yet). Reason: spec §16.3, and the injected storage lets the real file plugin drop in later.
- 2026-11-08 — Only mutable state is saved (vein reserve/scanned, ships, agents, resources, RNG state, logs, last decision, debug counters); planets, ores and balance are rebuilt from config. Reason: a rebalance or a new planet then applies to old saves. Missions, metrics and prompt versions join the save when their milestones exist.
- 2026-11-08 — `Persistence.save` refuses to overwrite a readable save with a different `schema_version`; `reset` forces it. `load`/`loadOrNew` never write and return `{code, message}` (`no_file` | `corrupt` | `unknown_schema`) for the UI to show. Reason: spec "unknown schema_version shows an error and does not overwrite the file" must also hold for autosave.
- 2026-11-08 — `saved_at` is passed in by the caller (the sim never reads a clock). The RNG state is `sim.rng.main`, a single stream until `rng.market` / `rng.events` / `rng.stub` exist. Reason: determinism, and a save resumes the exact stream (tested: restored game == original after 2500 more ticks).
- 2026-11-08 — Debug panel logic is `sim/debug.luau` (`Debug.run(sim, action, args, ctx)`), gated by `config/debug.luau` `enabled`; the view is `ui/debug.luau` (data entries + `spawn` with rtype.Ui, not yet run in the engine; the `debug_*` client→server messages wait for `net/protocol.luau` [ENGINE]). Reason: logic is testable headless, the view stays thin.
- 2026-11-08 — Debug actions whose system does not exist yet: `triggerShortage` calls `sim.market:forceEvent(kind, marketId, ore)` and reports "unavailable" until M6 provides it; `lastPrompt` shows the JSON context until the M2 prompt builder sets `lastDecision.prompt`; `simulateAway` just runs the sim with the AI detached (no skills exist) until M5's `offline.luau` replaces it; provider `rubix` is unavailable until GR5-15 calls `Ai.register("rubix", decide)`. Reason: expose the full spec'd panel now, fill in as the milestones land.
- 2026-11-08 — `setTier` sets `sim.tier` and every agent's `tier` (clamped 1..5, from config). `sim.debug.creditBoosts` counts credit boosts so the spec §17 demo budget (at most 1) is checkable with `Debug.withinDemoBudget`. The end-to-end demo path itself needs M2–M6 (mission 1, shop/scanner, skills, warehouse, Orbis) and cannot run yet.
- 2026-11-08 — GR5-25: agents are now registered by id with a `type` (`Sim:addAgent(id, kind)`, `Sim:addShip`, `Sim:addFreighter`); ships belong to an agent by `owner`. Agents/ships are stepped in registration order, never `pairs`, so multi-agent runs stay deterministic. Reason: crowding and conflicts need several agents, and `pairs` order is not stable.
- 2026-11-08 — GR5-25: crowding is computed each tick from the ships in `mining` state on the same vein; `crowded_by` (other agents' ids) lives on the ship, in `Sim:context().ship.crowded_by` and in a WARN log when the set changes, rather than in the `mine` return value (the sim's `apply` returns only ok/err and mining ends asynchronously). Reason: simplest place where the cause is visible to the feed and the logs.
- 2026-11-08 — GR5-25: thrashing guard (5 decisions / 30 s game time) and bailout numbers live in `balance.luau` (`ai.thrash*`, `bailout`); concurrency cap, hourly token cap and budget message live in `config/ai.luau` (spec §10.4). The guard logs once per agent and counts later episodes in `agent.throttleCount`. Reason: avoid log spam while staying observable.
- 2026-11-08 — GR5-25: bailout is an offer (`Sim.offer`, events `emergency_advance_offered/accepted/withdrawn`) that the UI turns into the notification button, accepted through `Sim:acceptEmergencyAdvance()`; the 5 min cooldown counts from acceptance. Reason: spec says "notification with a button", sim must not call UI.
- 2026-11-08 — GR5-25: Logistician `sell`/`ship` take `resource`/`qty`/`destination` (spec §11) and draw on the single shared warehouse stock at call time; check order is `not_bought_here` → `no_free_freighter` → `not_enough_stock`. Freighters are a minimal pool (busy out and back on the §5.2 routes, sold at base x demand with no saturation until the market milestone). Reason: lets the §8.6 conflicts exist now; full T4 freighter/station model stays in GR5-12.
- 2026-11-08 — GR5-25: `AiQueue` (sim/ai_queue.luau) is clock-injected; in the headless sim the clock is game time and tokens per decision are the placeholder `stubTokensPerDecision`; the real provider (GR5-15) must pass real seconds and real token counts. Agents with no Compute or a spent budget get state `no_compute` (reason in `agent.blockReason`). Reason: "per real hour" cannot be measured by a headless deterministic sim.
- 2026-11-08 — GR5-6 ships the Compute ledger, context builder/renderer/settings, prompt weights and the hourly AI budget as headless sim logic, plus pure view-models in `ui/compute_view.luau` (top bar, per-agent Compute/h, buy packs, Context panel). Screen drawing waits for the UI shell (GR5-3) and the engine UI plugin. Reason: neither exists yet; view-models keep the numbers testable and the screens only lay them out.
- 2026-11-08 — Token estimate is `ceil(utf8_len / 4)`; a decision costs `tokens / 1000` Compute rounded UP to 0.1. Charged on send with the estimate (input + `estimatedOutputTokens`), corrected on response with the real output size; a failed response is still billed for its input. Reason: the Context panel total must equal the billed estimate, and rounding up keeps the panel and the bill identical.
- 2026-11-08 — The hourly AI budget (400,000 tokens) is a rolling real-time window of 3600 s, injected clock for tests. Reached -> agent `no_compute` with reason `budget` and the message "Server AI budget reached", one WARN per transition. Reason: simplest rule that matches "per real hour" without a fixed reset boundary.
- 2026-11-08 — Per-agent Compute/h uses a 600 game-second rolling window (min 60 s elapsed before extrapolating). Reason: live enough to show who thinks too much, stable enough not to jitter.
- 2026-11-08 — Context toggles for locked features (Orbis/Halcyon/Meridian prices, warehouse) are reported `available = false` with their unlock tier and are left out of the prompt until the tier is reached. Reason: the panel weight must equal what the prompt really contains.
- 2026-11-08 — Only the Miner context builder exists; Logistician and Monitor builders arrive with their milestones (`builders` is keyed by `agent.kind`). Reason: T1 scope.
- 2026-11-08 — `warehouse.unlockTier` moved into `config/balance.luau` and `ai.computePerDecision` was removed in favour of `config/ai.luau`. Reason: balance numbers live only in config, and the per-decision cost is now derived from the real prompt size.
- 2026-11-08 — Integration of GR5-6 onto main (GR5-25 merged first): one AI budget authority, the `AiQueue` (concurrency cap + hourly tokens); the Compute ledger (`sim/compute.luau`) bills in Compute and asks the queue (`budgetReached`), so there is no second token log. `config/ai.luau` keeps the budget keys flat (`tokensPerHour`, `windowSeconds`, `budgetMessage`); `agent.blockReason` holds the player-facing message; one JSON codec (`sim/json.luau`, with `Json.map` for ordered objects and nil -> null). Reason: GR5-25 and GR5-6 each built a budget, a state flag and a codec.
- 2026-11-08 — GR5-15 Axis provider: `ai/axis.luau` runs the 4+1 call turn as a state machine over an injected transport (`send`/`poll`/`cancel`), `ai/provider.luau` adds queue, budget and validation, `server/axis_http.luau` is the only engine glue (`rtype.Http`, server only). Keys are never in Luau: headers carry `{{env:AXIS_API_KEY}}` / `{{env:AXIS_GATEWAY_KEY}}`, which the engine fills in, and `project.luau` declares `http.secrets` and `http.allowedHosts`. Reason: tests run headless on a fake network, and the client cannot see or leak a key.
- 2026-11-08 — Turn timeout is `timeoutSeconds = 20` in `config/ai.luau` (spec §8.4) although GR5-15 says 10 s; it is one value to change. Reason: spec overrides the ticket, and the turn is 5 sequential calls.
- 2026-11-08 — Provider failure (error, timeout, invalid reply, budget) logs an ERROR and the stub decider plays that decision; a schema-valid call the sim refuses is only logged by `apply`, and the thrashing guard (5 decisions / 30 game-s) stops it becoming a request loop. Reason: the game never stalls on the network.
- 2026-11-08 — Compute is charged on the token estimate at send and corrected to the real count on the answer (spec §6.4); both numbers are logged per decision ("tokens est N real M"). Json is our own module (`ai/json.luau`) because the engine has none; `ctx.time.elapsed`-style real seconds drive timeouts and the hourly budget.
- 2026-11-08 — The agent system prompt is cached for `systemPromptTtlSeconds = 600`, so most turns make 3 platform calls + 1 model call plus the fire-and-forget assistant turn and observe. Reason: it changes rarely and saves latency and requests across 9 groups.
- 2026-11-08 — Integration of GR5-15 (Axis) onto the unified sim: the `AiQueue` stays the only concurrency and hourly-budget gate, so `ai/provider.luau` no longer queues or budgets: the sim calls `provider:request` only when the queue lets a decision start, and `Sim:onAiResponse` settles the Compute charge on the real token count. One tool-schema format (`config/tools.luau`, typed args) feeds both the prompt text and the reply validator; one prompt builder (`sim/prompt.luau`, `Prompt.forProvider` adapts it); one codec (`sim/json.luau`, + `tryDecode`, depth limit, surrogate pairs). `ai/json`, `ai/tokens` and `ai/prompt` were removed. Reason: three PRs had each built their own copy of the same pieces.
- 2026-11-08 — GR5-4 on the unified sim: the default `Ai.decide` is now the spec §10.5 directive interpreter (`stub` mode; order read before directive; ore / vein id / planet / richest / nearest / hold % / scan; whatever is left open is random from its own `rng.stub` stream). The old always-optimal stub stays as mode `optimal`, `vague` as before. Reason: the player's wording must change the outcome; the stream is separate so a directive never shifts the world's randomness.
- 2026-11-08 — `mine` takes `stop_at_hold_pct` (10-100, default 100, spec §11): the ship heads home when the hold reaches it. The sim's own return (hold full / vein empty) is issued with `opts.auto` and has no feed line; the sale shows as an info line. Reason: those are not agent decisions, and the feed lists decisions with their results.
- 2026-11-08 — Error pauses (spec §8.4) live in `Sim:noteFailure`: 2 invalid responses (a refused call counts), 3 provider errors, or the same failing call twice in a row put the agent in `paused_error` until `Sim:resumeAgent`; a good decision from the agent's own decider resets the streak, a stub fallback after a provider failure does not. Reason: a fallback that succeeds must not hide a broken provider.
- 2026-11-08 — Vague vs precise (acceptance: >= 2x credits/min) is tested as a sum over 6 seeds, not per seed: single seeds range from x1.7 to x3.0 because the vague stub's random picks are lucky or not. Currently gross x2.12, net of Compute at the pack price x2.16.

- 2026-11-08 — GR5-3 theme: `config/theme.luau` holds 8 colours (bg, panel, text, dim, cyan, magenta, amber, green). The ticket lists 9 (a `line` #1E2A44 too); the border is `dim` at alpha 0.28 over `panel`, which keeps the "≤ 8" rule. Every other config names a colour (`"cyan"`), never a hex; `tools/check_palette.sh` (run by `tools/run_tests.sh`) fails on any hex outside the theme. Route lines: safe = cyan, risky = amber (the old blue/orange VFX values were outside the palette); error = amber, with the glitch.
- 2026-11-08 — GR5-3 panels: Pixel Holo UI (Helianthus Games, itch.io) could not be downloaded or its licence verified from the agent runtime, so panels are theme-coloured UI nodes (translucent `panel` fill, 1 px `dim` hairline, radius 4). They carry no baked glow, so the bloom rule holds (neon only). Dropping the pack in later means swapping `panel()` in `ui/shell.luau` for a 9-slice `image` tinted by the theme; nothing else changes.
- 2026-11-08 — GR5-3 font: JetBrains Mono Regular (SIL OFL 1.1, `assets/fonts/OFL.txt`, credit in `CREDITS_FONT.md`), baked to an MSDF atlas with msdf-atlas-gen from `assets/fonts/charset.txt` (ASCII + Latin-1 + arrows/box/bullets). It is the single font, wired through `Theme.font`; there is no Rajdhani title font.
- 2026-11-08 — GR5-3 sprite recolouring: ships/stations are one greyscale sprite per kind; `assets/shaders/palette_remap.glsl` + `client/remap.luau` map luminance onto a 4-step ramp (bg, panel, corporation neon, text) per corporation, so there is no per-corporation copy. The ramp lives in `Theme.remapRamp`.
- 2026-11-08 — GR5-3 map: planets are world sprites (shader), labels, route dashes and convoy dots are UI nodes at the same view-pixel positions (`Shell.mapPoint`, 1280x720 window = virtual resolution). Route lines are dashed dots rather than rotated lines so no sprite rotation is needed. The UI layer is rebuilt at most every 0.25 s and only when its signature changed (or a freighter is moving); the world layer only when a planet unlocks. Rebuilding ~150 small nodes at 4 Hz was chosen over a patch-per-node updater as the simplest thing that works; revisit if the profiler complains.
- 2026-11-08 — GR5-3 client: until the net protocol ([ENGINE]) replicates the sim, `client/main.luau` runs a local stand-in `Sim.new()` at 10 Hz so the shell shows real numbers. Only the windowed client loads it (`project.luau` sets `scripts.client` there); a headless client keeps no client script. Alignment of UI and world on the real GPU was not checked by eye (no screenshot possible in the agent runtime); the clean 15 s boot and the headless tests are the evidence.
